DRAFT SECURITY PROTOCOL & DISCLOSURE POLICY This technical overview summarizes the architecture and vulnerability reporting process for the E-Voting Pilot System. Independent third-party penetration testing and formal security accreditation are mandatory before live production usage.

Security Architecture & Responsible Disclosure

Electoral Integrity Standards • Spring Boot & Angular Architecture • October 2026

1. Multi-Layer Electoral Security Architecture

The pilot platform enforces defense-in-depth across the presentation, application, and persistence layers:

Backend Enforced Idempotency & Eligibility

Client UI validation is treated as advisory only. All authorization, role constraints, and voter eligibility checks are enforced by the Spring Boot microservices. Attempted duplicate submissions trigger an immutable 409 Conflict rejection.

Cryptographic Separation of Ballot Choices

Ballot choices are never stored alongside voter identification. The voting microservice computes cryptographic hashes of vote submissions to preserve aggregate verification without compromising secret ballot privacy.

Role-Partitioned Token Architecture

JSON Web Tokens (JWT) encode cryptographically signed role claims (VOTER, ADMIN, SUPER_ADMIN, AUDITOR, OFFICER). Cross-role access is denied at Spring Security filters and Angular functional route guards.

2. Responsible Vulnerability Disclosure Program

We encourage independent academic researchers and security engineers to responsibly review this pilot codebase and report potential vulnerabilities:

  • Guidelines: Do not disrupt live services, access voter privacy records, or execute destructive testing against shared environments.
  • Reporting Channel: Submit technical vulnerability reports with reproducible proof-of-concept steps to security-pilot@election-system.local.
  • Safe Harbor: Legitimate research conducted in good faith following these guidelines will not face legal action from the research project team.

3. Independent Audit and Verification Mandate

In accordance with public election best practices, software upgrades alone do not make an electronic voting platform production-ready. A formal security audit must encompass full source code scrutiny, hardware terminal tamper-resistance, and end-to-end cryptographic verifiability.
